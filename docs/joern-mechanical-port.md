# Mechanical Joern port: bounded first batch

The reference is **Joern v4.0.150**, source commit
`958fdd3d976197a783f8ade1254b43e977648f28`, paired with original
PyJoern 4.0.150.4. The frontend is Scala on the JVM **and depends on Eclipse
CDT's Java parser and bindings**. Translating the frontend does not translate
CDT, its overload resolution, templates, or object model.

The first production slice translates both complete operator-selection
matches in `AstForExpressionsCreator.scala`. `src/builder.rs` consumes the
generated functions; the old hand-maintained binary/unary tables are removed.
This is a behavior-preserving port/refactor, not a new C++ quality claim.

## What is mechanical, and what is an adapter?

| Part | Treatment |
| --- | --- |
| Binary match: 34 CDT operations and fallback | All branches parsed/checked; 32 have Rust lexical bindings; GNU max/min remain unsupported by the parser |
| Unary match: 13 CDT operations and fallback | All branches parsed/checked; 12 have Rust lexical bindings; parenthesized ASTs retain their existing separate owner |
| Schema operator strings | Exported from the original JVM, never inferred from constant names; some assignment operators use the plural `<operators>` prefix |
| CDT operation to Rust token | Explicit reviewed lexical adapter in the generator; not claimed to be translated CDT parsing |
| Allocation/deallocation | Existing Rust syntax uses unary nodes, CDT uses separate AST kinds; existing Rust adapter retained |
| Operand traversal, CFG, calls, types and bindings | Existing Rust owners retained; not newly ported in this batch |
| Original Scala assertions and fixture configuration | Not translated; imported snippets are source controls only |

The bounded translator rejects missing/default/duplicate branches, changed
source hashes, unknown constants and incomplete lexical adapters. It is not
a generic Scala-to-Rust transpiler. The checked-in original sources, Apache
license, JVM constants, commit and jar hashes live in
`tests/reference/joern-4.0.150/`. There are no new runtime dependencies.

## Repeatable loop

Fetch a pinned test/reference-only source checkout (outside tracked sources):

```sh
git clone --depth 1 --filter=blob:none --sparse --branch v4.0.150 \
  https://github.com/joernio/joern.git workspace/joern-port-4.0.150/source
git -C workspace/joern-port-4.0.150/source sparse-checkout set --no-cone \
  /LICENSE /joern-cli/frontends/c2cpg/src/ /joern-cli/frontends/x2cpg/src/
python3 scripts/joern_port/verify_reference.py \
  --source workspace/joern-port-4.0.150/source --joern /path/to/original/joern-cli
python3 scripts/joern_port/generate_operators.py --check
python3 scripts/joern_port/import_fixtures.py \
  --source workspace/joern-port-4.0.150/source \
  --output workspace/joern-port-4.0.150/imported
```

The importer tokenizes Scala strings and nested comments. Every `code(...)`
call gets an audit record. Literal inputs retain hashes, source lines and
upstream identity. Interpolation, composition, unknown filenames and
parameterized suite configuration require review. `.moreCode`, include
paths, preprocessing options, postprocessing and Scala assertions are **not
replayed**: even accepted inputs are explicitly source-only controls, not
proof of an upstream test passing. Import failure stops the inventory rather
than dropping a file. `INVENTORY.json` lists main modules, methods and CDT
references so subsequent batches can be planned by owner/dependency.

Use the existing isolated/checkpointed runner on every accepted input:

```sh
cargo build --release
python3 scripts/qualify_corpus.py \
  --inputs workspace/joern-port-4.0.150/imported/INPUTS.json \
  --library target/release/librust_joern.dylib \
  --output workspace/joern-port-4.0.150/upstream-controls \
  --joern-loop-conditions --jobs 3
```

For selected literal sources, use `scripts/compare_pyjoern.py` with the
unchanged original interpreter, `--save-reference-dir` and `--output`. Compare
identical bytes. Report missing/extra functions, diagnostics, directed CFG
topology, entry/exit roles and degeneracy; do not replace a failed comparison
with an expected graph generated by Rust. Full CPG properties and effect
ordering need additional evidence: CFG topology alone cannot prove them.

After each batch, replay the frozen real-input pool in both default and
Joern-loop profiles using `qualify_corpus.py` and
`compare_qualification.py`. Freeze libraries and wrappers before comparisons.
Keep all original failures and denominator entries; source controls are not
benchmark binaries or an expansion of the scored population.

## Subsequent port boundaries

The generated inventory is a work list, not a percentage-complete claim.
Next modules must expose their CDT requirements before translation:

1. Expression AST construction: operand ordering, receiver/argument edges,
   typed versus unresolved calls. Keep parser facts distinct from unresolved
   bindings; no stub that claims a resolved CDT type.
2. Statement CFG: branches, loops, jumps, exception constructs, then
   constructor/destructor effects. Track intentional original-Joern losses
   separately in `divergences.md`.
3. Function/type owners: declarations, templates and native type identity.
   These require a typed semantic contract, not textual Scala replacement.

DecBench settings, Rust-Joern dependency pin, scores and population are left
unchanged by this batch. Local evidence is recorded under
`workspace/joern-port-4.0.150/`; it is not a public ranking update.

The [2026-10-25 pilot report](eval/joern_port_2026-10-25.md) records the actual
measurements, unavailable original comparisons and remaining work.
